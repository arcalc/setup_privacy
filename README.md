# Security DNS

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![Platforms](https://img.shields.io/badge/platform-Linux%20%7C%20Windows-blue.svg)](#requirements)

**Security DNS** hides your DNS lookups from your Internet Service Provider (ISP), makes it harder for Deep Packet Inspection (DPI) equipment to read website names, and gives you an interactive menu to switch between three protection modes. It is installed as a local application with a menu, a `.desktop` entry on Linux, and Start Menu and Desktop shortcuts on Windows.

Every change is backed up before it is made, and the uninstaller restores those exact backups.

## The Modes

The first installation enables encrypted DNS and starts **Mode A**. You can switch modes at any time from the menu. Only one routing mode is active at once. Every switch stops the current mode before it starts the next.

| Mode | What it does | Keeps your public IP? | Hides destination IPs from ISP? |
|---|---|---|---|
| **A. SpoofDPI bypass** | Local DPI-bypass proxy that splits the TLS handshake, plus encrypted DNS | Yes | No |
| **B. Cloudflare WARP** | Official Cloudflare client. All traffic goes through an encrypted tunnel to Cloudflare | No | Yes |
| **C. WireGuard (wgcf)** | WireGuard tunnel using a WARP profile generated by `wgcf` | No | Yes |
| **O. Off** | Stops the proxy and tunnels. Keeps encrypted DNS | Yes | No |

Modes B and C are a trade-off, not a free upgrade. Read [Location and IP Address Trade-off](#location-and-ip-address-trade-off) before you enable them.

Encrypted DNS is always on:

- **Linux:** DNS-over-TLS (DoT) through `systemd-resolved` with `1.1.1.1` and `1.0.0.1`. `DNSOverTLS=yes`, `DNSSEC=allow-downgrade`, and `Domains=~.` send every lookup through these resolvers. `FallbackDNS=` is empty, so queries do not leak to DHCP or hardcoded fallback servers.
- **Windows:** DNS-over-HTTPS (DoH) with Cloudflare templates on active physical adapters, with UDP fallback disabled. This requires Windows 10 version 2004 (build 19041) or newer, including Windows 11. Older builds keep their existing DNS and show a warning, so queries are never sent in plaintext.

## What Is and Is Not Hidden

No local tool can make your ISP completely blind. The table shows what each mode protects.

| Information | Mode A | Mode B / C | Mode O |
|---|---|---|---|
| DNS lookups (which domains you resolve) | Hidden | Hidden | Hidden |
| Website name in the TLS handshake (SNI) | Mostly hidden (fragmentation; full on ECH sites when ECH is enabled) | Hidden inside the tunnel | Mostly hidden |
| Destination IP addresses | **Visible** | **Hidden** (ISP sees only a connection to Cloudflare) | **Visible** |
| Traffic volume and timing | Visible | Visible, as traffic to Cloudflare | Visible |
| Your public IP address | Unchanged | Changes to a Cloudflare address | Unchanged |
| Your apparent country | Unchanged | **May change** | Unchanged |
| QUIC / HTTP/3 traffic | Visible unless disabled in the browser | Tunneled | Visible unless disabled |
| Apps that ignore system proxy settings | Not protected | Protected while the tunnel is up | Not protected |

With Modes B and C, your ISP still knows you are connected to Cloudflare, and Cloudflare can see your traffic. The protection comes from trusting Cloudflare instead of your ISP. Check the laws in your country regarding circumvention and privacy tools before you use them. WARP may be restricted or blocked in some places.

## Location and IP Address Trade-off

You asked for complete ISP blindness to destination IPs without changing where websites think you are. These two goals conflict, and no tool here can satisfy both.

- A tunnel that hides destinations from your ISP must send your traffic out from somewhere else.
- WARP exits from the Cloudflare data center closest to you. That data center may be in another country, so websites that geolocate by IP may show you in that country.
- A VPN with an exit server in your own country keeps your apparent location, but then the VPN provider sees your destinations instead of your ISP.

The menu warns you before it switches to Mode B or C and asks you to confirm. After switching, verify your apparent location with an IP geolocation site, comparing the result in Mode A (or Off) with the result in Mode B or C. If your apparent country changes and that matters for the sites you use, switch back to Mode A or Off.

## Requirements

**Linux**

- x86_64 (amd64) and systemd with `systemd-resolved`
- Root access through `sudo`
- apt-based (Debian, Ubuntu) or dnf-based (Fedora, RHEL family) for Mode B; Mode C uses `wireguard-tools` from your package manager
- Network access to `api.github.com`, `github.com`, `1.1.1.1`, `pkg.cloudflareclient.com`, and `raw.githubusercontent.com`
- A desktop environment with `x-terminal-emulator` for the application menu entry (the command-line menu works everywhere)

**Windows**

- Windows 10 version 2004 (build 19041) or newer, including Windows 11, for system-wide DoH
- Windows PowerShell 5.1 or PowerShell 7, in an elevated (Administrator) session
- Network access to `api.github.com`, `raw.githubusercontent.com`, `downloads.cloudflareclient.com`, and the WireGuard release downloads

## Installation

### Linux

```bash
curl -fsSL https://raw.githubusercontent.com/arcalc/setup_privacy/main/install.sh | sudo bash
```

The first run:

1. Installs missing base tools (`curl`, `wget`, `tar`, `iproute2`, `ca-certificates`).
2. Backs up `resolved.conf`, `/etc/resolv.conf`, `/etc/environment`, and each desktop user's GNOME and KDE proxy settings.
3. Installs the application to `/usr/local/bin/security-dns`, the uninstaller to `/usr/local/lib/security-dns/uninstall.sh`, and a desktop entry.
4. Downloads the latest SpoofDPI release (verified with SHA-256 when a checksum is published).
5. Configures DNS-over-TLS.
6. Starts Mode A and sets the system and desktop proxy automatically.
7. Opens the menu.

To open the menu later, run:

```bash
sudo security-dns
```

You can also launch **Security DNS** from your applications menu. It opens a terminal and asks for your password.

### Windows

Open **PowerShell as Administrator** and run:

```powershell
irm https://raw.githubusercontent.com/arcalc/setup_privacy/main/install.ps1 | iex
```

The first run:

1. Backs up the proxy registry values, per-adapter DNS settings, DoH entries, and any existing startup launcher.
2. Installs the application to `C:\ProgramData\SecurityDNS`, with the menu script and uninstaller.
3. Enables DNS-over-HTTPS on active physical adapters (or shows a warning on older builds).
4. Downloads the latest SpoofDPI release and starts Mode A, with the system proxy set automatically.
5. Creates **Security DNS** shortcuts in the Start Menu and on the Desktop. Both run the menu as administrator.

Open the menu later from the shortcut, or run `& "C:\ProgramData\SecurityDNS\security-dns.ps1" -Menu` from an elevated PowerShell.

> **Security note:** Piping a remote script into PowerShell or a shell runs code you have not read. Download the file first with `irm ... -OutFile`, review it, and then run it, especially on machines you care about.

## Using the Menu

```text
  Security DNS v2.0.0                 current mode: A

  [A] Mode A: SpoofDPI bypass       keeps your public IP; DPI bypass and encrypted DNS
  [B] Mode B: Cloudflare WARP       hides destination IPs; changes your public IP
  [C] Mode C: WireGuard (wgcf)      hides destination IPs; changes your public IP
  [O] Off: stop proxy and tunnels   keeps encrypted DNS
  [S] Status
  [U] Check for updates
  [X] Uninstall and restore original settings
  [Q] Quit
```

Choosing **B** or **C** shows a warning and asks you to confirm before anything changes. Choosing **A** or **O** applies immediately.

What each switch does:

- **Stops everything first:** the SpoofDPI service or process, the WireGuard tunnel, the WARP connection, and the automatic proxy settings.
- **Then starts only the chosen mode.** Mode B installs and registers the WARP client if needed, then connects. Mode C creates a WireGuard profile with wgcf if needed, then starts the tunnel. Mode A starts SpoofDPI and sets the proxy.
- **Records the mode** in the state file, so the menu and the uninstaller know what is active.

Mode B and C installs are added only when first used. Packages and tools that were already on the system are left in place when you uninstall.

## Updates

Choose **U** in the menu, or run `sudo security-dns --update` on Linux (Windows: choose U in the menu). The update check covers:

- **The script:** compares the version with the one in the repository and, after your confirmation, replaces the menu and the uninstaller. A downloaded script is syntax-checked before it replaces the current one.
- **SpoofDPI:** resolves the latest release from the GitHub API and installs it only if it differs from the installed version.
- **wgcf:** resolves the latest release and installs it if it differs.
- **Cloudflare WARP:** upgraded through your package manager on Linux. The Windows client updates itself.

After a script update, reopen the menu to use the new version.

## Browser Settings

Two browser settings complement the tool. Neither replaces the other.

### Enable ECH

**Encrypted Client Hello (ECH)** encrypts the Server Name Indication (SNI) field, which otherwise reveals the website name. It only protects connections to sites that publish ECH keys, and the browser fetches those keys through DNS. ECH works best together with the encrypted DNS configured by this tool.

- **Firefox:** open `about:config`, then set `network.dns.echconfig.enabled` and `network.dns.http3_echconfig.enabled` to `true`.
- **Chrome, Edge, and other Chromium browsers:** open `chrome://flags/#encrypted-client-hello` and set it to **Enabled**, then restart the browser. Option names change between versions, so search the flags page for "ECH" if you cannot find it.

### Disable QUIC / HTTP/3

QUIC runs over UDP and does not pass through an HTTP proxy. Left enabled, it can bypass SpoofDPI in Mode A and expose the hostname.

- **Firefox:** in `about:config`, set `network.http.http3.enable` to `false`.
- **Chromium:** open `chrome://flags/#enable-quic` and set it to **Disabled**.

### Manual proxy (window managers the script does not detect)

- **Address:** `127.0.0.1`
- **Port:** `8080`, or `8081` if 8080 was busy at install time
- **Protocols:** HTTP and HTTPS
- **Exceptions:** `localhost, 127.0.0.0/8, ::1`

## Verifying the Setup

**Linux**

```bash
sudo security-dns        # then choose S for status
resolvectl status        # the global section should show DNSOverTLS and 1.1.1.1 / 1.0.0.1
ss -ltn | grep -E ':(8080|8081)\s'
curl -I -x http://127.0.0.1:8080 https://example.com   # Mode A only
```

**Windows**

```powershell
Get-DnsClientDohServerAddress     # should list 1.1.1.1 and 1.0.0.1
Get-NetTCPConnection -State Listen -LocalPort 8080,8081 -ErrorAction SilentlyContinue
```

To confirm your apparent location and IP address, open an IP geolocation site in a browser in each mode and compare the results.

## Uninstalling

Choose **X** in the menu, or run:

```bash
sudo bash /usr/local/lib/security-dns/uninstall.sh          # Linux
```

```powershell
& "C:\ProgramData\SecurityDNS\uninstall.ps1"                 # Windows, elevated
```

The uninstaller:

- Stops SpoofDPI, WireGuard, and WARP.
- Disconnects and removes WARP only if Security DNS installed it. A WARP client that was already present is left alone.
- Removes the WireGuard profile, `wgcf`, and the WireGuard tools only if Security DNS added them.
- Restores `resolved.conf`, `/etc/resolv.conf`, `/etc/environment`, and each user's GNOME and KDE proxy settings. On Windows it restores DNS, DoH entries, the proxy registry values, and the startup launcher.
- Removes the service, the SpoofDPI binary, the menu, the desktop entry, and the Start Menu and Desktop shortcuts.
- Deletes the backups only after everything is restored.

If a desktop user's GNOME settings cannot be restored because that user is not logged in, the uninstaller keeps its backups and reports the pending step. Log in as that user and run the uninstaller again.

## Troubleshooting

**Ports 8080 and 8081 are both busy.** Stop the application using them, then run the installer again.

**Mode B or C shows "not connected".** Check the tool directly: `warp-cli status` on Linux (or the Windows path `C:\Program Files\Cloudflare\Cloudflare WARP\warp-cli.exe status`), or `systemctl status wg-quick@security-dns` on Linux. Security DNS keeps DNS encryption working even when a tunnel fails, so you can switch to Mode A or Off from the menu.

**Mode B or C changed my apparent country.** This is the exit-location trade-off described above. Switch back to Mode A or Off if it matters for the sites you use.

**Websites fail in Mode A.** Check the service with `systemctl status security-dns` (Linux) or `Get-Process spoofdpi` (Windows). If the proxy is down, switch to Mode O from the menu.

**Windows reports that DoH is not supported.** Your build is older than 19041 (Windows 10 version 2004). Enable Secure DNS in your browser instead: in Chrome or Edge, use Settings, Privacy and security, Security, Use secure DNS, and choose Cloudflare. In Firefox, use Settings, Privacy & Security, DNS over HTTPS.

**NetworkManager overrides DNS on Linux.** Make sure NetworkManager uses `systemd-resolved` (`dns=systemd-resolved`).

**The Windows menu does not open from the shortcut.** Make sure you approve the administrator prompt. Shortcuts point to `C:\ProgramData\SecurityDNS\security-dns.ps1`. If that file is missing, reinstall.

## Security Notes

- The scripts store no credentials and send no personal data. Network requests go only to the GitHub API and release downloads, Cloudflare's WARP package and download servers, and the DNS resolvers you configured.
- SpoofDPI listens only on `127.0.0.1`.
- Downloads are verified with SHA-256 when the release publishes checksums. Otherwise the installer prints a warning.
- The Linux WARP repository is signed with Cloudflare's key, which is stored as a keyring file and removed on uninstall.
- Updates are syntax-checked before they replace the installed script.
- To avoid GitHub API rate limits, set `GITHUB_TOKEN` to a read-only personal access token before running the installer.
- Report security issues through GitHub's private vulnerability reporting, not as public issues.
